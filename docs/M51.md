# M51 — Persistent Project Factory

## Goal

Make the project factory durable across process restarts and move long-running factory execution out of the HTTP request path.

## What changed

- Added a SQLAlchemy-backed `factory_projects` table.
- Factory project mission, plan, status, stage count, and update time are persisted.
- Queued and interrupted-running projects can be restored into the in-memory queue.
- Added background execution with `asyncio.create_task`.
- Added `POST /api/missions/{mission_id}/factory-run`.
- Added `GET /api/factory/status`.
- A bounded run can use `max_stages=1..12`.
- Paused projects are returned to the queue and can resume from their persisted plan.
- Added tests for pause/resume and restoration.

## Recovery model

A project persisted as `running` is restored as `queued` after a process restart. This prevents an interrupted process from permanently consuming a project.

The current recovery endpoint starts the restored queue explicitly. Automatic process-start execution is intentionally deferred so a restart cannot unexpectedly launch model workloads without an operator action.

## Boundary

M51 provides durable project-factory state and background execution. It does not claim that the specialist stages themselves have all external GitHub, deployment, monitoring, or learning integrations implemented.
