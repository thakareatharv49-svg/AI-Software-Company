# M36 — End-to-End Autonomous Project

## Purpose

M36 composes the company's existing autonomous subsystems into one bounded project run.

The run is:

1. Mission intake and AI CEO approval.
2. Research.
3. Research handoff to product/engineering.
4. Product definition.
5. Architecture definition.
6. Engineering, QA, debugging, security review and GitHub through the existing end-to-end pipeline.
7. Deployment through an explicit deployment adapter.
8. Monitoring through an explicit monitoring adapter.
9. Learning from the completed project execution.
10. Dashboard snapshot of the run.

## Implementation

`src/company/autonomous_project.py` provides:

- `AutonomousProjectRequest` — complete input contract for one project run.
- `AutonomousProjectRunner` — bounded orchestration boundary.
- `AutonomousProjectResult` — durable result containing every major stage.
- `StageResult` / `StageStatus` — explicit stage outcomes.

The runner deliberately requires deployment and monitoring hooks. It does not pretend that a project is fully delivered when those capabilities are absent.

## Integration

M36 composes, rather than duplicates:

- M31 AI execution coordination where applicable.
- M32 real-world research.
- M33 collaboration and research handoffs.
- M34 company dashboard.
- M35 learning.
- The existing company execution pipeline for project creation, task execution, QA, autonomous debugging, security review, GitHub integration, recovery and project memory.

## Acceptance test

`tests/integration/test_m36_autonomous_project.py` runs a complete bounded project with:

- CEO approval
- research evidence
- agent handoff
- product and architecture artifacts
- engineering execution
- QA
- security review
- GitHub pull-request creation using an in-memory GitHub client
- deployment hook
- monitoring hook
- learning signal
- dashboard snapshot

The test uses deterministic adapters so the full lifecycle is reproducible without requiring an external model or deployment service.
