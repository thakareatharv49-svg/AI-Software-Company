# M48 — Agent Execution Pipeline

## Goal

Connect the M47 mission plan to the existing agent engine so planned stages can be executed one at a time.

## Flow

1. M47 creates the 12-stage mission plan.
2. M48 maps the next planned stage to a specialist agent.
3. The existing AgentExecutor receives the stage objective as an AgentRequest.
4. A successful result marks the stage completed and selects the next stage.
5. A failed result marks the stage failed and blocks the company.
6. Company events expose stage start, success, failure, and readiness.

## Agent mapping

Every mission stage has a deterministic specialist name such as research-agent, product-agent, and qa-agent. Agents are registered with the existing AgentRegistry when execution starts.

## Runtime

M48 reuses AgentExecutor and AIRuntime; it does not create a second agent execution system. A real provider must be configured by the application, such as the existing Ollama provider.

## Boundary

M48 executes one stage per call. It does not claim that all 12 stages execute automatically in one request, and it does not invent GitHub, deployment, or monitoring actions. Those capabilities remain future integrations.

## Acceptance criteria

- A planned stage reaches AgentExecutor.
- Successful execution advances the company to the next stage.
- Failed execution blocks the company and emits a failure event.
- The 12-stage plan remains intact.
- Existing control-center and M47 behavior remains compatible.
