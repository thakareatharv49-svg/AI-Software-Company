# M60 — Production Readiness Gate

M60 is the release-readiness milestone for the autonomous software company.

## Readiness API

`GET /api/company/readiness`

The endpoint returns `ready`, the active environment, and individual readiness checks.

The gate verifies:
1. debug mode is disabled;
2. a database URL is configured;
3. the AI runtime endpoint and model are configured;
4. GitHub writes are either disabled or authenticated;
5. the environment is explicitly `production`.

## Release rule

A deployment should only be treated as production-ready when `ready` is `true`.

The gate is intentionally configuration-based. It does not pretend that external services are reachable merely because their URLs exist. Deployment, GitHub, research, monitoring, and AI provider connectivity must still be validated by the deployment environment's own smoke tests.

## Final architecture

M47–M50 provide mission planning and autonomous stage execution.

M51–M54 provide persistence, scheduling, recovery, cancellation, and retry controls.

M55–M56 provide durable audit history and operator visibility.

M57–M58 provide durable output manifests and output observability.

M59 connects the factory to the existing M36 artifact-producing autonomous runner through an explicit adapter.

M60 provides the final release gate and makes production configuration requirements observable.

## Scope boundary

The repository is structurally complete through M60, but production operation still requires real credentials, reachable services, database migrations, and deployment infrastructure to be configured outside the repository. The readiness endpoint deliberately reports configuration readiness rather than fabricating successful external connectivity.
