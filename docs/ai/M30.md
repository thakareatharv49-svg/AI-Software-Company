# M30 — AI Execution History & Persistence

## Goal

Persist AI execution metadata across process restarts.

## Implementation

M30 introduces a JSONL-backed execution history store.

### Components

- `AIExecutionHistoryRecord`
- `AIExecutionHistoryStore`

The history layer converts M29 execution observations into immutable records and
persists them as newline-delimited JSON.

## Persistence

Each execution is stored as one JSON object per line.

The store supports:

- append
- list
- run ID filtering
- actor filtering
- lookup by run ID
- latest execution lookup
- reload after process restart

## Security Boundary

History intentionally stores execution metadata only.

It does **not** persist:

- prompts
- tool arguments
- tool outputs
- tool errors
- secrets

This keeps the history layer suitable for long-running autonomous execution
without turning the history file into a raw execution-data dump.

## Validation

M30 requires:

- history record conversion tests
- persistence/reload tests
- filtering tests
- empty-store behavior tests
- metadata-only persistence tests
- Ruff validation
- full regression validation
